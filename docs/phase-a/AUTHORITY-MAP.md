## Rules for reading the map

- A module registered in the kernel is **not** automatically allowed to write a registry. Check that registry's exact caller gate. In particular, `isAuthorizedModule` is not a universal write permission.
- A registry gate and an application's political/role checks are different layers. A broad registry writer must be reachable only through narrowly approved application methods.
- Production script addresses below describe [Deploy.s.sol](../../scripts/Deploy.s.sol#L580). Preparation parks Congress and referendum authority on setup; `completeGenesis` activates the apps in a later confirmed-block stage. It does not establish an actual deployment.
- [KernelModule._isActiveSetupAuthority](../../contracts/base/KernelModule.sol#L48) requires nonzero **kernel bootstrap authority** and the matching `INITIAL_SETUP_AUTHORITY` caller. It does not itself check `isSealed`; [InitialSetupAuthority](../../contracts/apps/InitialSetupAuthority.sol#L384) separately rejects owner calls after sealing. The primary `STAKE_REGISTRY_AUTHORITY` slot can still point to that now-inert setup contract after bootstrap. Check both conditions in inventory.
- President and executive registries additionally accept the kernel bootstrap caller directly. OfficeRegistry has **four** allowed routes: ordinary authority, DecisionApp, CabinetApp and active setup fallback. Do not infer a sole writer from the ordinary slot alone.
- Retired loan-book owners and original budget commitment authorities retain narrow settlement rights. Repointing today's slot does not revoke these captured permissions.
- Existing SenateApp supplies bounded negative controls. Existing Senate presidential election is a separate HeadOfStateApp workflow. New Senate adjudication/recovery powers still need the precise body/authority/threshold inputs under L01/L03/L04/L06. Acceptance of independent review did not select an unstated second body.

## Full current eligibility and snapshot dependency closure

A pointer-only `CITIZEN_ELIGIBILITY_POLICY` replacement does not update immutable references below. Every intended new bundle must be constructed and checked as one consistent dependency graph; old live processes keep their original policy references until the L10 transition says otherwise.

```text
new referendum -> kernel-current VotingPowerPolicy
new election -> kernel-current CongressElectionPolicy
CongressElectionPolicy -> immutable CandidateEligibilityPolicy + VotingPowerPolicy
VotingPowerPolicy -> immutable CitizenEligibilityPolicy + ElectorateRegistry
VotingPowerPolicy -> immutable IdentityRegistry + StakeRegistry
CandidateEligibilityPolicy -> immutable CitizenEligibilityPolicy + IdentityRegistry + StakeRegistry
CitizenEligibilityPolicy -> immutable IdentityRegistry + StakeRegistry
ElectorateRegistry -> immutable IdentityRegistry + StakeRegistry + kernel-live citizen policy
identity/stake source callback -> kernel-current ElectorateRegistry
active referendum/cycle -> stored policy bundle + snapshot block
```

The diagram names shared references, not one mutable global object. Both voting and candidate policies independently pin their citizenship-policy address. The implemented membership restriction source is not connected to this graph yet. A time-aware `ElectorateRegistryV2` remains an unproved design candidate: do not certify expired aggregates or claim a no-op identity write solves clock expiry.

### Proposed caller-to-effect restrictions

| Caller | Named writer operation it may request | Must never gain |
|---|---|---|
| AdmissionPipeline | Register applicant, record scoped verification, admit on its approved route, initial wallet consent | Arbitrary citizenship/status assignment; bypass of route-specific approvals |
| AnnulmentApp | Exact prospective annulment after the required lawful decision, response/review/stay checks | Generic disciplinary revocation or arbitrary metadata rewrite |
| DisciplineCaseApp | Precisely approved membership order, stay, revocation or restoration | A citizenship transition; arbitrary stake slash; arbitrary office dismissal |
| CommissionDecisionApp | Typed scoped evidence/metadata correction where approved; determinations consumed by the correct workflow | General identity mutation from a bare decision ID |
| RecoveryApp | Exact exceptional active-link replacement with old-link/nonce/destination consent | Old wallet's private key or arbitrary external assets; bypass of hearing/notice |
| Current active person | Exact self-renunciation/resignation or old+new consent migration where authorised | Modification of another person's record |
| Typed CompensationApp/settlement | Exact approved reservation/settlement/restoration through canonical integrated accounting | Generic seizure, future-deposit consumption, unbacked restoration or treasury withdrawal |
| LandDisputeCaseApp | Exact lawful version-bound remedy submitted to the single land writer | Registrar powers, arbitrary calls or unlimited owner/geometry rewriting |
| Permissionless operator | Submit eligible execution, sync, expiry or manifest proof transaction | Select decision content, alter subject/effect, invent service or substitute a migration leaf |

A proposed receipt binds issuer/domain, subject/matter, stage/revision, legal version/body context, exact effect and expected old state/version. The recognised issuer must atomically consume it for its permitted writer after **effect-specific effective/final/stay conditions** hold. Interim measures must not accidentally wait for final removal conditions. A failed registry write rolls receipt consumption back; no raw arbitrary callbacks. Old issuer continuity is an L10 decision, not an unlimited historical-issuer allowlist.
